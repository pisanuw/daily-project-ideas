# Project Ideas for 2026-06-26

## 1. Design System Scribe
**Category:** Side Project
**Complexity:** Weekend
**Inspired by:** google-labs-code/design.md trending on GitHub — a format spec that gives AI coding agents a persistent, structured understanding of a project's visual identity (https://github.com/trending)

### Description
A web app that crawls any website URL and auto-generates a design.md file capturing its complete visual language: color palette (hex values + semantic roles), typography scale, spacing tokens, border radius, and recurring UI patterns. The output is a structured document that AI coding agents like Claude Code can read to keep new components visually consistent with the rest of the site.

### Key Features
- URL-based crawl that screenshots pages and extracts CSS variables, computed styles, and DOM patterns
- Claude API analysis that maps raw values to semantic design tokens (e.g., "primary", "surface", "on-surface")
- One-click download of a formatted design.md plus an optional design-tokens.json for tooling integration
- Live preview panel showing a rendered component generated strictly from the extracted tokens

### Suggested Tech Stack
React + Vite + Tailwind for the UI, Puppeteer (headless Chromium) for page crawling and screenshots, Claude API for semantic analysis and design.md authoring, Supabase for caching recent crawl results

### Why It's Interesting
The design.md format is an emerging standard for communicating visual identity to AI coding agents, and there is currently no automated way to generate one. This fills that gap instantly and positions you in a fast-moving niche before the ecosystem hardens around a tool.

## 2. Collaborative Debug Room
**Category:** Teaching Tool
**Complexity:** 1-2 Weeks
**Inspired by:** Real-time collaboration features in TREK (self-hosted trip planner with live collab trending on GitHub) and HN "Ask: What are you working on? June 2026" thread showing hunger for multiplayer dev tooling (https://news.ycombinator.com/item?id=48528779)

### Description
A multiplayer, in-browser debugging environment where an instructor drops in a broken code snippet and students collaboratively diagnose the bug. One student at a time is the "driver" with edit access; the rest annotate individual lines with their hypothesis. When the group has been stuck for more than two minutes, a Claude-powered AI facilitator sends a targeted Socratic hint without giving away the answer.

### Key Features
- Real-time presence: colored cursors show who is looking at which line, annotations appear instantly for all participants
- Driver rotation: instructor or a timer can pass editing rights to the next student in queue
- Hypothesis threads: any participant can attach a hypothesis card to a line, others can upvote or refute it
- AI facilitator with a configurable hint budget per session so instructors control how much help the AI provides
- Session replay: after the bug is fixed, the full annotation timeline plays back as a learning artifact

### Suggested Tech Stack
React + Monaco Editor for the coding surface, Supabase Realtime (Presence + Broadcast channels) for multiplayer sync, Flask backend for AI facilitation logic, Claude API for hint generation, Tailwind for styling

### Why It's Interesting
Most classroom debugging tools are either passive screencasts or one-student-at-a-time demos. This makes the whole class active participants in every debug session, which dramatically increases engagement and surfaces the diversity of mental models students hold about the same bug.

## 3. Model Distillation Lab
**Category:** Classroom Assignment
**Complexity:** Multi-week
**Inspired by:** Needle (Gemini Tool Calling behavior distilled into a 26M parameter model) surfaced in the HN "What are you working on? June 2026" thread, and OSSInsight trending repos showing specialized small models dominating 2026 (https://ossinsight.io/trending/ai)

### Description
Students build a complete teacher-student knowledge distillation pipeline from scratch. They pick a specific capability (e.g., "classify code smells" or "generate docstrings"), use the Claude API as the teacher model to generate a labeled dataset of input-output pairs, fine-tune a small open-weights model with LoRA via Ollama or Hugging Face, and then evaluate how faithfully the student model replicates the teacher's behavior across a held-out test set. A web dashboard lets them visualize alignment and divergence between teacher and student outputs.

### Key Features
- Dataset curation UI: students write seed prompts, the teacher model generates responses, and students flag low-quality examples before training
- LoRA fine-tuning pipeline wired to a local Ollama instance so training happens on student hardware without cloud GPU costs
- Evaluation dashboard comparing teacher vs. student outputs side-by-side with automated semantic similarity scoring
- Capability drift monitor: a chart showing how student accuracy degrades as inputs move further from the training distribution

### Suggested Tech Stack
Python (FastAPI backend), Claude API for teacher generation, Ollama for local fine-tuning inference, Hugging Face PEFT library for LoRA, React + Recharts for the evaluation dashboard, Supabase for storing datasets and run results

### Why It's Interesting
Knowledge distillation is one of the most commercially important techniques in modern ML yet almost no undergraduate courses teach it hands-on. This assignment gives students a concrete, end-to-end pipeline that demystifies how small specialized models are built from large general ones.
