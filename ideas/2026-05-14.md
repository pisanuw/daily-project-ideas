# Project Ideas for 2026-05-14

## 1. Vibe Rubric
**Category:** Side Project
**Complexity:** Weekend
**Inspired by:** EdWeek's May 2026 report on AI-powered "vibe coding" saving school districts $200K (https://www.edweek.org/technology/a-district-expects-to-save-200k-from-ai-powered-vibe-coding-heres-how/2026/05) and the broader shift toward AI-assisted instructor workflow

### Description
An instructor pastes a CS assignment description in plain English, and the AI generates a grading rubric, a model solution, and three calibration examples at distinct quality tiers (A, B, F). Every section of the rubric is editable via a natural-language command ("make the efficiency criterion worth more" or "add a style section"). The goal is to compress rubric authoring from hours to minutes while keeping the instructor in full control.

### Key Features
- Plain-English assignment input generates a structured rubric with weighted criteria
- AI produces a short model solution and three annotated student-submission examples at A, B, and F quality levels for calibration
- Inline natural-language rubric editing: type a change request and the rubric updates in place
- Export to Markdown or Canvas-compatible JSON for immediate classroom use

### Suggested Tech Stack
React + Vite + Tailwind for the UI, Claude API (claude-sonnet-4-6) for rubric and calibration generation, Supabase for saving and sharing rubric drafts

### Why It's Interesting
A professor who teaches 3 courses a term spends hours per assignment writing rubrics; this tool turns that into a 10-minute conversation, and the calibration examples make grading more consistent across TAs.

## 2. Socratic Debugger
**Category:** Teaching Tool
**Complexity:** 1-2 Weeks
**Inspired by:** Reddit r/AI_Agents discussion threads (early May 2026) on AI agent reliability for real work tasks (https://dev.to/lura_cardena_7de06f82aacd/ai-agents-on-reddit-late-april-to-early-may-2026-ten-threads-about-cost-reliability-and-real-4f20) combined with classroom need to prevent AI from just handing students answers

### Description
A professor creates a "course instance" and configures which error types the AI may explain directly vs. must handle Socratically. Students paste runtime errors, tracebacks, or broken code snippets and receive guiding questions instead of fixes: "What does line 14 actually return when x is 0?" The AI tracks each student's session history and after each debugging conversation generates a short report flagging recurring misconceptions for the instructor.

### Key Features
- Instructor dashboard to configure Socratic strictness per topic (e.g., "always Socratic for null pointer errors, allow hints for syntax errors")
- Student-facing chat that responds to error pastes with questions, never direct answers, unless the student is genuinely stuck after 5 exchanges
- Per-session and per-student pattern reports exported as a summary the instructor can skim in under a minute
- Anonymous mode so students are not afraid to share embarrassing errors

### Suggested Tech Stack
React + Vite + Tailwind frontend, Flask backend, Supabase for session and pattern storage, Claude API for Socratic question generation and session summarization

### Why It's Interesting
It directly counters the most common AI-in-education complaint ("students just paste code into ChatGPT and copy the answer") by making the AI itself enforce active learning, while still giving instructors visibility into where the class is struggling.

## 3. Accessible Game Jam Platform
**Category:** Classroom Assignment
**Complexity:** Multi-week
**Inspired by:** GitHub trending repository `roboflow/supervision` (computer vision tooling) and the May 2026 Hacker News Show HN post on a browser-based accessibility checker (https://news.ycombinator.com/item?id=44597777), combined with the growing focus on accessibility-first design in 2026

### Description
Students build small browser-based games (canvas or DOM, any framework) and submit them to a shared platform that automatically scores each game on four accessibility dimensions: keyboard-only navigation, color contrast ratios, ARIA label coverage, and screen-reader flow. An AI then generates a prioritized list of specific code-level fixes. A public leaderboard ranks submissions by accessibility score, creating friendly competition around an often-neglected engineering concern.

### Key Features
- Automated scanner runs WCAG 2.2 checks against submitted game URLs and produces a numeric score per dimension
- AI generates actionable, code-specific fix suggestions (not generic WCAG citations) ranked by impact
- Public leaderboard with per-student score history so students can see improvement across iterations
- Instructor panel to set a minimum accessibility score as a submission requirement, enforcing it before a grade is recorded

### Suggested Tech Stack
React + Vite + Tailwind for the platform UI, Flask backend with axe-core or pa11y for automated WCAG scanning, Claude API for translating scan results into human-readable code-level fix suggestions, Supabase for submission and score storage

### Why It's Interesting
Game jams already create strong student motivation; adding an accessibility leaderboard forces students to think about disabled users in a context where they are genuinely invested in the outcome, making the lesson stick far better than a lecture on WCAG guidelines.
