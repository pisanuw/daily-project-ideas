# Project Ideas for 2026-05-19

## 1. Skill Scout
**Category:** Side Project
**Complexity:** Weekend
**Inspired by:** GitHub trending (May 2026) showing a surge in Claude Code skills repos - mattpocock/skills, everything-claude-code, and similar repositories dominating the top 10, signaling a community hungry for a central discovery layer

### Description
A searchable web registry that indexes public GitHub repositories containing Claude Code slash commands and skills, letting developers find, preview, and copy-install community-built behaviors in seconds. Users paste a GitHub URL or browse by tag (coding, writing, DevOps, education) and see the command name, what it does, and a one-click copy of the install snippet. Think npm registry but for reusable AI agent behaviors.

### Key Features
- GitHub API crawler that indexes repos tagged with `claude-code-skill` or matching naming patterns
- Full-text search over command names, descriptions, and README content
- Preview panel showing the raw `.md` file and sample invocations
- One-click copy of the `cp` or `curl` install command
- Trending / recently-added feeds so the community surfaces good work

### Suggested Tech Stack
React + Vite + Tailwind for the frontend, Flask or Supabase Edge Functions for the GitHub crawler backend, Supabase for indexing and search (pg_trgm), Claude API to auto-summarize commands that lack good README descriptions

### Why It's Interesting
The Claude Code skills ecosystem is exploding right now with no central discovery layer, so this fills a real gap immediately and would attract genuine users within days of launch. It is also a clean teaching example of building a developer-tools product on top of GitHub's public API.

## 2. Bias Lens
**Category:** Teaching Tool
**Complexity:** 1-2 Weeks
**Inspired by:** AI ethics coverage in education tooling (nerdbot.com, is4.ai May 2026 roundups) and gaps in existing classroom tools for hands-on bias detection beyond simple quizzes

### Description
A classroom web app where students paste or upload text corpora, CSV datasets, or code files and receive an AI-powered bias audit broken into three dimensions: linguistic bias (stereotyping, loaded language), representation bias (which groups appear, how often, in what roles), and algorithmic bias (for code, which inputs get different treatment). Each finding links to a plain-English explanation and a mitigation suggestion. The instructor dashboard aggregates class submissions to spark discussion.

### Key Features
- Multi-modal input: plain text, CSV upload, GitHub file URL, or paste code
- Three-category bias report with severity ratings and highlighted excerpts
- Side-by-side "before / after" view when students apply a suggested fix and re-analyze
- Instructor view showing all student submissions aggregated by bias category
- Export report as PDF for portfolio or assignment submission

### Suggested Tech Stack
React + Vite + Tailwind, Flask backend, Claude API (claude-sonnet-4-6) for the bias audit with structured JSON output, Supabase for storing submissions and instructor aggregates, pdf-lib for report export

### Why It's Interesting
This turns AI ethics from an abstract lecture topic into an empirical lab exercise where students actively discover bias in real data they chose, making the concept concrete and memorable. It fills a genuine gap: most classroom AI ethics tools are reading-based, not hands-on analytical.

## 3. Accessibility Audit Bot
**Category:** Classroom Assignment
**Complexity:** Multi-week
**Inspired by:** Growing emphasis on WCAG 2.2 compliance in professional web development and the "openhuman" open-source entry on GitHub trending (May 2026) signaling renewed interest in human-centered, accessible software

### Description
Students build an automated web accessibility auditing agent: given a target URL, it crawls the site, runs WCAG 2.2 checks (contrast ratios, missing alt text, keyboard traps, ARIA misuse, etc.), then calls the Claude API to translate each raw violation into a plain-English explanation and a concrete code-level fix recommendation. The agent opens GitHub issues for each violation and re-audits after fixes are committed to measure improvement over time.

### Key Features
- Playwright-based crawler that extracts DOM snapshots and computes basic WCAG checks client-side
- Claude API call per violation to generate natural-language explanation and suggested HTML/CSS fix
- GitHub integration: auto-create issues labeled `a11y`, assign severity, link to WCAG criterion
- Re-audit mode that diffs before/after violation counts and produces a remediation score
- Final report dashboard showing violation trends across the project lifecycle

### Suggested Tech Stack
Python + Playwright for crawling and WCAG checks, Claude API (claude-sonnet-4-6) for natural-language remediation advice, PyGitHub for issue creation, Flask + React + Tailwind for the dashboard, Supabase for storing audit runs and issue status

### Why It's Interesting
This project teaches three high-value professional skills at once: web accessibility standards, AI agent workflows, and CI/CD thinking (audit, fix, re-audit). The GitHub integration makes the feedback loop concrete and the deliverable is immediately applicable to any real project a student maintains.
