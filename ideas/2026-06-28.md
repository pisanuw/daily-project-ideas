# Project Ideas for 2026-06-28

## 1. Doc DX Grader
**Category:** Side Project
**Complexity:** Weekend
**Inspired by:** HN "Ask HN: What developer tool do you wish existed in 2026?" (https://news.ycombinator.com/item?id=46345827) and the explosion of AI-generated docs that are often incomplete or inconsistent

### Description
A React web app where you drop in the URL (or paste the text) of any developer documentation page and receive a structured DX quality report graded A-F across five dimensions: getting-started speed, code example completeness, error scenario coverage, parameter clarity, and conceptual overview depth. Claude API reads the page content, quotes specific problem sentences, and generates 2-3 actionable improvement suggestions per dimension. A shareable report link lets you send the results to a docs team.

### Key Features
- Five-dimension scorecard (getting-started, code examples, error coverage, parameter clarity, overview depth) with letter grades
- Quoted citations from the actual docs text for each issue found
- 2-3 concrete improvement suggestions per dimension generated by Claude API
- Shareable report URL stored in Supabase so you can send results to a docs team
- Side-by-side before/after preview showing a rewritten example section

### Suggested Tech Stack
React + Vite + Tailwind, Flask backend for URL fetching and Claude API calls, Supabase for saving/sharing reports

### Why It's Interesting
Every developer has hit documentation that wastes an hour of their time, but giving specific, structured feedback to docs teams is hard — this makes it a one-click action and produces output concrete enough to act on.

## 2. Pair Programming Pulse
**Category:** Teaching Tool
**Complexity:** 1-2 Weeks
**Inspired by:** HN "Ask HN: What are you working on? (June 2026)" (https://news.ycombinator.com/item?id=48528779) discussion on developer collaboration analytics, and HackAbility AI for Accessibility 2026 pushing hands-on skills assessment

### Description
A web app where student pairs paste or upload the text log from any paired coding session (VS Code Live Share chat, Zoom transcript, or a plain text log). Claude API analyzes the exchange and produces a structured collaboration quality report: estimated driver-to-navigator time ratio, frequency and quality of think-alouds, how the pair handled blockers, and specific moments where communication broke down. Instructors get a class-wide dashboard showing pair effectiveness per assignment, surfacing which student pairings need coaching.

### Key Features
- Transcript upload (plain text, JSON, or Zoom .vtt) with automatic speaker labeling
- Claude API analysis measuring think-aloud rate, question quality, and blocker-handling patterns
- Per-session PDF report with timestamped highlight clips and rubric scores
- Instructor dashboard showing class-wide pair effectiveness heatmap per assignment
- Anonymized comparison so students can see how their session compares to the class median

### Suggested Tech Stack
React + Vite + Tailwind frontend, Flask backend, Claude API for transcript analysis, Supabase for session storage and instructor dashboard, PDF export via Puppeteer

### Why It's Interesting
Pair programming is taught in nearly every CS course but almost never assessed — grading the code tells you nothing about whether the collaboration happened. This gives instructors a scalable window into the actual pairing process.

## 3. WebGPU Shader Studio
**Category:** Classroom Assignment
**Complexity:** Multi-week
**Inspired by:** HN "Show HN: ChartGPU – WebGPU-powered charting library" and "Show HN: A game where you build a GPU" (https://news.ycombinator.com/front), plus the growing list of WebGPU compute tools on GitHub trending June 2026

### Description
A multi-week classroom project where students implement a full in-browser WGSL compute shader development environment using the WebGPU API. The app includes a Monaco editor for writing shaders, an animated canvas that visualizes thread-group execution as a live grid of colored cells, and a benchmarking panel that compares shader runtime against a JavaScript CPU baseline. A Claude API assistant explains what each pipeline stage does, flags common WGSL pitfalls, and suggests optimization strategies. Students complete a curriculum of five challenges (parallel reduction, prefix scan, matrix multiply, bitonic sort, image blur) and publish their fastest solutions to a class-wide gallery.

### Key Features
- Monaco editor with WGSL syntax highlighting and error underlining
- Animated thread-group visualization showing dispatch dimensions and workgroup occupancy
- CPU vs. GPU benchmark panel with real execution times and speedup ratio
- Claude API assistant that explains each shader stage, flags WGSL errors, and suggests optimizations
- Five graded challenge levels (parallel reduction through image blur) with automated correctness tests
- Class gallery where students publish and star each other's fastest implementations

### Suggested Tech Stack
Vanilla JS or React + Vite for the UI, WebGPU API (native browser), Monaco Editor (npm), Claude API for the AI coach, Supabase for the challenge gallery and leaderboard

### Why It's Interesting
WebGPU reached stable support in all major browsers in 2025 but almost no CS curriculum has caught up — this project teaches students a genuinely modern skill (GPU compute) while building something visually impressive that runs entirely in a browser tab.
