# Project Ideas for 2026-06-17

## 1. Screenshot-to-Spec
**Category:** Side Project
**Complexity:** Weekend
**Inspired by:** Show HN "One Human + One Agent = One Browser From Scratch" (news.ycombinator.com/item?id=46779522) and the rise of vision-capable AI agents doing visual UI tasks

### Description
Drop a screenshot of any UI (a web app, a mobile screen, a Figma mock) and the tool generates a structured product requirements doc: page sections, component hierarchy, copy, user flows, and acceptance criteria. It bridges the gap between "I saw this design I like" and "I need to build something like it" without requiring Figma access or a designer.

### Key Features
- Paste or drag-and-drop any screenshot for instant analysis
- Outputs structured spec: sections, components, copy strings, and user flows
- Editable output with export to Markdown or Notion-style format
- Optional "tech stack suggestion" mode that recommends implementation approach

### Suggested Tech Stack
React + Vite + Tailwind for the UI, Claude API with vision for image analysis, Supabase for saving and sharing specs

### Why It's Interesting
Vision-capable LLMs make this feasible in a weekend but the output is genuinely useful to any solo dev or student who reverse-engineers designs for learning; it also doubles as a teaching tool for UI decomposition.

## 2. Student Confusion Heatmap
**Category:** Teaching Tool
**Complexity:** 1-2 Weeks
**Inspired by:** "Ask HN: What developer tool do you wish existed in 2026?" (news.ycombinator.com/item?id=46345827) and the trend of always-on ambient coding assistants

### Description
A VS Code extension paired with a real-time teacher dashboard that anonymously tracks where students slow down, backspace repeatedly, or hover longest during a coding assignment. The teacher sees a live per-file, per-line heatmap of class-wide confusion so they can intervene at exactly the right moment instead of waiting for office hours.

### Key Features
- VS Code extension captures pause duration, undo frequency, and cursor dwell time per line
- Data streams anonymously to Supabase in real time
- React dashboard shows a color-coded heatmap of the starter code file, updated live
- Teacher can click any hot line to see an AI-generated "likely confusion reason" based on code context

### Suggested Tech Stack
TypeScript VS Code extension API, Supabase Realtime for streaming events, React + Recharts for the dashboard, Claude API for generating line-level confusion explanations

### Why It's Interesting
It turns the invisible private struggle of learning to code into observable signal the teacher can actually act on, moving classroom support from reactive (office hours) to proactive (live intervention).

## 3. Tiny 2D Game Engine
**Category:** Classroom Assignment
**Complexity:** Multi-week
**Inspired by:** Show HN "One Human + One Agent = One Browser From Scratch in 20K LOC" (news.ycombinator.com/item?id=46779522) — if a browser can be built from scratch as a learning project, so can a game engine

### Description
Students build a minimal 2D game engine from scratch using only the browser Canvas API with no game frameworks allowed (no Phaser, no Three.js, no p5.js). The project is scaffolded into weekly milestones that end with students demoing a playable game built entirely on their own engine.

### Key Features
- Week 1: game loop with fixed timestep and delta-time rendering
- Week 2: sprite sheet animation and scene graph
- Week 3: AABB collision detection and resolution
- Week 4: input manager, audio, and a complete playable demo game
- Optional extension: add a simple Entity-Component System (ECS) architecture

### Suggested Tech Stack
Vanilla JavaScript, Canvas API, Vite for hot-reload during development; no game library dependencies permitted

### Why It's Interesting
Building an engine before using one forces students to understand what every abstraction actually does, making them dramatically better at debugging when they later use Phaser or Unity; the constraint of "no framework" is what makes the learning stick.
