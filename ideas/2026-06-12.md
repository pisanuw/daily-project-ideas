# Project Ideas for 2026-06-12

## 1. Voice Rubber Duck Debugger
**Category:** Side Project
**Complexity:** Weekend
**Inspired by:** Web Speech API + the growing trend of voice-first developer tools; the rubber duck debugging technique formalized with AI Socratic questioning

### Description
A browser app where developers talk through their code problem out loud using the Web Speech API. An AI transcribes the monologue, identifies gaps or contradictions in the reasoning, and responds with one Socratic clarifying question at a time — never giving the answer directly. The session ends with a "thinking clarity" summary showing where the reasoning broke down.

### Key Features
- Voice capture via Web Speech API with live transcript display
- Claude API configured to only ask questions, never provide direct solutions
- Annotated session summary highlighting logical gaps and moments of clarity
- Shareable session link so students can show instructors how they reasoned through a problem

### Suggested Tech Stack
React, Vite, Tailwind, Claude API, Web Speech API, LocalStorage (no backend needed for MVP)

### Why It's Interesting
Rubber duck debugging is a proven technique, but adding AI-powered Socratic feedback that stays in "question mode" makes it genuinely useful for teaching students to articulate their thinking rather than just wait for answers.

## 2. Syllabus Semantic Diff
**Category:** Teaching Tool
**Complexity:** 1-2 Weeks
**Inspired by:** The "Understand-Anything" document understanding trend on GitHub trending (June 2026) and the real professor pain of revising courses without knowing how changes affect student experience

### Description
A professor-facing web tool where you upload two versions of a course syllabus (PDF or pasted text) and receive a semantic comparison: topics added or dropped, estimated workload shift, learning objective alignment score, and a plain-English student-experience summary. Goes far beyond a text diff by analyzing intent and coverage changes.

### Key Features
- PDF ingestion and text extraction with PDF.js
- Side-by-side semantic topic diff (not just text diff) using Claude API
- Workload delta estimate (hours per week, reading load)
- Learning objective alignment check against Bloom's taxonomy levels
- Export summary as PDF for department review or accreditation files

### Suggested Tech Stack
React, Vite, Tailwind, Flask, Claude API, PDF.js, Supabase (for saving comparison history)

### Why It's Interesting
Professors revise courses every year but rarely have visibility into how their changes affect student experience. This gives a concrete reflection tool that also doubles as evidence for teaching portfolios and program reviews.

## 3. Multi-Agent Conversation Replay Studio
**Category:** Classroom Assignment
**Complexity:** Multi-week
**Inspired by:** The explosion of multi-agent frameworks on GitHub trending (June 2026) and the need for students to understand agent orchestration beyond toy examples

### Description
Students build a tool that orchestrates two or more AI agents toward a shared goal (debating architecture choices, collaborating on code review, negotiating API design). The UI records the full conversation graph as a timeline, lets users scrub back to any message, branch from any decision point to explore alternate outcomes, and compare final outputs across branches side-by-side.

### Key Features
- Agent role and system-prompt configuration panel
- Animated conversation timeline with scrub-back capability
- Branch/fork from any message node to explore alternative paths
- Side-by-side diff of two branch outcomes
- Export full run as JSON for reproducibility and grading

### Suggested Tech Stack
React, Vite, Tailwind, FastAPI or Flask, Claude API (for multiple agents), Supabase (run storage), React Flow (conversation graph visualization)

### Why It's Interesting
As multi-agent systems become standard in industry, hands-on experience orchestrating agents and comparing their decision paths is a concrete differentiator — and the replay/branching UI makes the invisible reasoning process visible and debuggable.
