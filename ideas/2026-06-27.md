# Project Ideas for 2026-06-27

## 1. Intent Drift Detector
**Category:** Side Project
**Complexity:** Weekend
**Inspired by:** HN "Statewright – Visual state machines that make AI agents reliable" (May 2026) and "I scanned 16 AI agent repos – 76% of tool calls had no guards" — both pointing to a growing need to understand when agents lose track of the original goal

### Description
A React web app where you paste in an LLM conversation transcript and it visualizes semantic drift across turns — showing as a color-coded timeline how far each assistant response moved from the user's original stated intent, measured via embedding cosine similarity. When the line dips red, the agent has lost the thread.

### Key Features
- Paste or upload a conversation JSON/text transcript
- Compute embeddings for each turn against the original user intent sentence
- Render a drift graph (turn vs. similarity score) with annotated "derail points"
- Click any turn to see which phrases diverged most from the original goal
- Export a summary report (useful for debugging agentic pipelines)

### Suggested Tech Stack
React + Vite + Tailwind for the UI; Claude API or Gemini Embeddings API for embeddings; Recharts for the drift graph; optional Supabase for saving/sharing transcripts

### Why It's Interesting
Agentic AI reliability is the hottest topic in 2026 and this tool gives developers a visual, immediate way to see where their agent went off-rails — something that's currently only possible by reading transcripts line by line.

## 2. Accessibility Challenge Arena
**Category:** Teaching Tool
**Complexity:** 1-2 Weeks
**Inspired by:** GitHub Blog "Beyond the engine: 10 open source projects shaping how games actually get made" (EdenSpark accessibility-first engine launch) and the broader push for hands-on a11y education in CS curricula

### Description
A gamified web app that gives CS students a sequence of progressively harder accessibility challenges: each level presents a broken UI component (missing ARIA labels, poor color contrast, no keyboard trap fix, etc.) and students write the correction directly in a code editor, then hit "Check" to run axe-core against their fix in-browser. Instructors create custom challenge packs from their own course code.

### Key Features
- 20 built-in challenge levels covering WCAG 2.1 A/AA violations
- In-browser code editor (CodeMirror) with live preview and instant axe-core feedback
- Leaderboard per class section with time-to-solve and hint-count scoring
- Instructor dashboard to add custom challenges by pasting any HTML snippet
- Hint system powered by Claude API that explains the specific violation in plain language

### Suggested Tech Stack
React + Vite + Tailwind; CodeMirror for the editor; axe-core (npm) for automated a11y testing; Supabase for auth, scores, and instructor challenge packs; Claude API for hint generation

### Why It's Interesting
Most a11y education is passive (read the WCAG docs) or automated (run a scanner). This is the first gamified, hands-on fix-it format that gives students immediate feedback on code they actually write — and it scales to any instructor's existing assignments.

## 3. Agent Safety Ruleset Studio
**Category:** Classroom Assignment
**Complexity:** Multi-week
**Inspired by:** HN "I scanned 16 AI agent repos – 76% of tool calls had no guards" (May 2026) and "SkillFortify – formal verification for AI agent skills" (Feb 2026) — a clear trend toward specifying and enforcing safety properties on AI tool definitions

### Description
Students build a web tool that lets users write a set of safety rules for AI agent tools in a simple YAML-based DSL (e.g., "all tools must have a description," "tools that write files must list affected paths," "no tool may accept wildcard permissions"), then point it at an MCP server's tool manifest and receive a structured safety report with pass/fail per rule and suggested fixes. Students define the DSL, write the parser, build the auditor, and design the report UI.

### Key Features
- YAML DSL editor with syntax highlighting and live validation
- MCP server URL input that fetches and parses the tool manifest
- Rule engine that checks each tool definition against the active ruleset
- Color-coded safety report with per-tool violations and severity levels
- Claude API integration to auto-suggest fixes for each violation
- Save and share ruleset "profiles" (e.g., "Production Safety," "Student Sandbox")

### Suggested Tech Stack
Flask backend (DSL parser, MCP manifest fetcher, rule engine); React + Vite + Tailwind frontend; Supabase for ruleset profiles and shared reports; Claude API for fix suggestions; Monaco Editor for the DSL

### Why It's Interesting
It teaches three hard things at once: formal specification thinking, AI tool safety design, and building a real developer-facing tool — and it produces something genuinely useful as the MCP ecosystem explodes with unaudited third-party servers.
