# Briefing

- Purpose: Automated daily project idea curation via Claude Code Remote Trigger. Since 2026-11-02 the site is framed as "ideas I could build for you": every idea modal ends with a mailto asking to build it, and the hero links to the built apps.
- Current scope: Daily 5am routine (ROUTINE.md) gathers demand signals and commits 3 to 6 commercially viable product ideas (1 to 3 more in an extra run) (schemaVersion 3) to pisanuw/daily-project-ideas; a static website (Netlify; canonical address https://daily-project-ideas.pisan.me since 2026-11-02, built apps at https://<folder>.pisan.me) renders the ideas grouped by complexity
- Routine quality controls (2026-10-30): 15 to 20 scored candidates, gate (total >= 22, pain >= 4, WTP >= 3, 2 independent evidence items, one within 90 days), adversarial review per idea, watchlist for near misses, weekday source rotation, full-history dedup via ideas/index.jsonl, scripts/validate_ideas.py before commit
- Routine revision (2026-11-01), after the first five v3 runs produced zero ideas between them: the gate numbers are unchanged, but a run now always ships at least one idea. Ideas that clear the gate are `confidence: validated`; otherwise the best reviewed candidate ships as `provisional` with a `gateGap` naming what it misses. Three logic fixes: a killed idea no longer empties the day (continue down the ranked list), `pain` above 3 requires a complaint-kind evidence item, and the higher-ed constraint is relaxed from "half must be educational" to "at least one, at most 2 per category", with a weekday domain lens that points most days outside education (since 2026-11-02 small business gets two days, Thursday back office and Friday customer-facing, matching the owner's customer priority)
- Reachability (2026-11-01): the catalog `ideas/sources.json` now names a verified access path and client per source instead of a brand. Reddit, G2/Capterra, Product Hunt, Indie Hackers, Chrome Web Store reviews and the Canvas Community are unreachable from the routine's sandbox and are on an avoid list; Stack Exchange and some news indexes work only via curl, not WebFetch. New reachable veins: Discourse `/search.json` on any instance, WordPress plugin API and support forums, GitHub API, HN Algolia, Federal Register, NSF awards, OpenAlex
- Self-diagnosis (2026-11-01): every run appends a record to `ideas/run-log.jsonl` (sources, every fetch and its outcome, the candidate funnel, the gate condition each candidate died at, and `floorFailure` when a run ships nothing). `scripts/source_health.py` turns the log into `ideas/source-health.md`, which the routine reads at Step 0. Intent: tune the routine from recorded evidence rather than by editing the prompt on a hunch
- Key decisions: Remote Trigger on Sonnet 4.6, pushes to main, ideas stored in ideas/YYYY-MM-DD.md with index in IDEAS.md. Website built by zero-dep build.js into dist/ (Netlify build = `node build.js`, publish = dist). Landing page groups by complexity pepper tiers (Weekend 🌶️ / 1-2 Weeks 🌶️🌶️ / Multi-week 🌶️🌶️🌶️) plus an Implemented section; cards show a 1-2 sentence summary and open a detail modal. build.js prefers ideas/YYYY-MM-DD.json over .md; routine should emit JSON + summary going forward (ideas/SCHEMA.md). Implemented projects are hand-curated in implemented.json. Email notification (added 2026-10-25, previously a non-goal): a GitHub Actions job runs scripts/notify-implemented.mjs daily at 9:10am Pacific (crons at 16:10 and 17:10 UTC, the early one dropped by a Pacific-hour guard so DST does not shift it), diffs implemented.json against notify-state.json, and sends at most one Resend digest a day to yusuf.pisan@gmail.com; the writeup mirrors pisanorg.github.io/yusuf/aiprojects (title linked to the live site, the entry's notes split at the limitations sentence, README and live links, implementation date). Credentials are GitHub secrets RESEND_API_KEY/FROM_EMAIL/ADMIN_EMAIL, mirrored in a git-ignored .env for local dry runs.
- Non-goals: No local cron, no manual curation step (idea generation). Implemented-project curation is the one intentional manual step.
- Small business first (2026-11-02, owner): four of seven weekday lenses point at small businesses (Mon compliance, Thu back office, Fri customer-facing, Sun makers and freelancers); every run includes at least 5 small-business candidates; the day's floor is one small-business idea (`Small Business Ops` or optional `smallBusiness: true`), replacing the one-EdTech-idea floor. Feasibility 5 now means a standalone web app with no paid API on the owner's key, since chosen ideas are built into claude-built-apps and mirrored to the pisan-labs org.
- More and better ideas (2026-11-04, owner): in 8 runs no candidate cleared the gate (total 22), mostly because willingnessToPay sat at the evidence cap of 2 while G2, Capterra, Product Hunt and Indie Hackers are blocked. New spend sources B11 (freelance job boards: freelancer.com API, PeoplePerHour) and B12 (paid app marketplaces: Shopify App Store, Atlassian), new complaint source A15 (Make, Bubble, n8n, Zapier communities); a spend pass on every candidate at 17+; the top 3 watchlist entries are re-researched each first run and drop after 14 stale days; a first run ships 3 to 5 ideas (up to 4 provisional). Gate numbers unchanged.
- HintWise Studio (2026-11-08, owner): the site is the HintWise company showcase at https://studio.hintwise.org. Home = hero, 6 featured apps (StepWise, Poincare Paint, Digital Student Assistant, Bombe Bench, Cache Miss Theater, Health Page Tracker Watch), audiences, how it works, about (Yusuf Pisan, Chief Education Officer). /apps/ lists every built app with audience filters (Small businesses, Educators, Developers, Learners) and search; /apps/<slug>/ per app. The daily ideas moved to Next up (/next-up.html, browse, topics); the routine is unchanged. Catalog data: studio.json; pages: build-studio.js; images: web/media/ via scripts/studio_media.js. App links are <app>.hintwise.org (build rewrites any old pisan.me app link). Contact builder@hintwise.org. Public pages carry no scores, evidence, competitors, build time, tech stack or test counts.
- Weekly build (2026-11-09, owner): claude-built-apps now builds one substantial project a week (up to 7 agent build days) on the HintWise platform: static front end on Netlify, a shared Supabase project (Google or magic-link sign-in, one Postgres schema per app, row level security), an LLM gateway where the visitor brings their own Anthropic key or uses the owner's key behind caps, and backend-hub on Render for anything else. From 2026-11-10 every idea carries a `shape` rubric (stateful, connected, unattended, engine, shared), `substantial` (two or more marks), `platformNeeds`, and a `buildPlan` of 5 to 7 milestones when it is substantial and Multi-week; a day needs one such idea or a `runNotes.caveats` line. Feasibility 5 now means a 7-day build on the platform, replacing the standalone-no-paid-API wording that rewarded single-page calculators. Daily volume (3 to 5), Weekend MVP ideas and every gate number are unchanged; Weekend MVPs still ship to the site but are never picked for a build. `scripts/validate_ideas.py` checks the new fields on files dated 2026-11-10 or later.
